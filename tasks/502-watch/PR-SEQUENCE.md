# PR sequence for #502

Each PR has one concern. PR 0 is the plan: it gives every later PR a row and an issue, except
PR 1, PR 3a and PR 3b, which start now (PR 1 and PR 3a answer #501; PR 3b is a plain bug fix with
its own issue). PR 0b amends the plan for amendment 1 (`AMENDMENT-1.md`) and adds no row. Each
row's check is what proves it done, and each row's budget is in
`tasks/502-watch.md` (budget). The role column follows `kitimark-mode`. "Owner merges" means the PR
touches a path the owner keeps (`gate/`, `.github/`, `.claude/`, `docs/process.md`, `plan/`). A PR
that touches `gate/` or `.github/` is trust-critical, so it also needs an `opus` verdict at `xhigh`
or above; a PR that touches only `.claude/`, `docs/process.md` or `plan/` is owner-merged with a
normal verifier. Every PR adds its run-log file under `ops/runs/`. Only PR 0 and PR 0b touch
`plan/`; the issues were filed first, so PR 0 links them, and PR 0b keeps every link. A row's Files column is the whole set that PR may change, and it
overrides `HANDOVER.md`'s default "must not" list for that PR only (PR 3c and PR 11 need it, and so does every Lean row that extends a `Watch` module an earlier row made).

The Lean rows (2, 3c, 4, 5, 6, 7a, 7b, 7c, 8) are at contract depth: the sketch was never
type-checked. Before a Lean row's PR owner starts, the Architect type-checks that row's slice,
writes the stub bodies its statements are stated over, and upgrades the row's task file to build
depth (`tasks/502-watch.md`, Design). PR 1 and PR 3a are at build depth: their diffs ran against `main`
at `7dfd6cb`.

The order puts the stopgaps first, then the plan, then pure modules before IO, and deletes the old
code last. Each merged PR leaves `main` working. The root's rules change in three places only:
PR 1 changes the Watchers text on how the bash watcher tells an agent's comment from the owner's,
PR 13 switches the waiting rules to `watch.sh`, and PR 15 removes the bash watcher's fallback
paragraph.
